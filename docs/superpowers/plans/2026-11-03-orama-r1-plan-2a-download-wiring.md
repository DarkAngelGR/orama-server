# Orama Release 1 — Plan 2a: Download-side wiring Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** After `apply`, Prowlarr, Sonarr, Radarr, SABnzbd and qBittorrent (behind Gluetun when the VPN is on) are connected to each other through their own APIs, and running `apply` again changes nothing.

**Architecture:** The Orama container joins a shared Docker network (`orama-net`) so it can reach every app by service name. A new `orama.wiring` package holds one module per app, each with check-then-act steps. A small step engine runs them in dependency order and prints a plain checklist. SABnzbd and qBittorrent cannot take their credentials from the environment, so the Agent gets one new allowlisted command, `seed-config`, which writes only fixed, validated keys into those apps' config files.

**Tech Stack:** Python ≥3.12 stdlib `urllib` (no new HTTP dependency), pydantic 2, pytest; app REST APIs (Sonarr/Radarr v3, Prowlarr v1, SABnzbd `/api`, qBittorrent WebUI API v2); Gluetun env options.

**Spec:** `docs/superpowers/specs/2026-11-03-orama-release-1-design.md` (§5.3.3 wiring, §4.5 network, §5.1 idempotent apply, §5.3.4 failures). Read `docs/superpowers/plans/2026-11-03-orama-r1-plan-1-notes.md` first: it records how Plan 1 was actually built and overrides the Plan 1 text.

**Scope split (owner decision):** this plan covers the download side. **Plan 2b** (written after this one) covers Bazarr, Recyclarr + device profiles (§6.1–6.2), Plex sign-in, Jellyfin first run, and Sonarr/Radarr → Plex/Jellyfin connections. The Sonarr/Radarr webhook to Orama belongs to Plan 4 (requests).

**Model policy (owner decision):** use the cheaper model (`sonnet`) for implementers and reviewers by default. Use the most capable model (`opus`) only for tasks marked **[opus]**: those that change the Agent, the compose/validator pins, or secret handling.

## Global Constraints

- Everything in the Plan 1 Global Constraints still holds (see the Plan 1 plan and notes).
- The Agent is the only component with the Docker socket. Every new Agent input is allowlisted and validated, and the Agent never trusts paths or file formats sent by Orama.
- Orama talks to apps only over `orama-net`, by service name and **container** port (`http://sonarr:8989`, never host ports).
- Each app's API key or password is generated by Orama, kept in `SecretStore`, and never written to `compose.yaml`, logs or command output.
- Every wiring step is check-then-act: it reads the current state and changes only what differs. Running `apply` twice must report no changes the second time (spec §5.1).
- Orama manages only entries it created. They are identified by fixed names: `SABnzbd (Orama)`, `qBittorrent (Orama)`, `Sonarr (Orama)`, `Radarr (Orama)`, and by root-folder path. Entries the user added are never edited or deleted.
- All user-facing output is plain language: it says which app, what happened, and what to do.
- Commits go straight to `main` with trailer `Co-Authored-By: Claude …` and no `Claude-Session:` line.

## Review Focus

1. **App still starting** (first-start database migrations can take minutes) → the step waits up to its timeout, then reports "<App> is still starting — run apply again in a few minutes". No crash. **[T3]**
2. **A re-run after a partial failure** → the second run finishes the missing steps without creating duplicate download clients, indexers or applications. **[T5–T8]**
3. **The user edited an Orama-managed entry in an app's own UI** (e.g. changed the SABnzbd host) → apply restores only the fields Orama manages and leaves the user's own entries untouched. **[T6]**
4. **Secrets with awkward characters** (`&`, `=`, `%`, `+`, space, `#`, Greek) in a Usenet password or indexer API key → sent correctly encoded to SABnzbd's query API and to JSON APIs. **[T5, T8]**
5. **A download method switched off later** (torrent removed) → the `qBittorrent (Orama)` client is removed from Sonarr and Radarr, user-added clients stay, and the qBittorrent config folder is kept. **[T6]**

### Task 2 [opus]: Agent `seed-config` for SABnzbd and qBittorrent

**Files:**
- Create `src/orama_agent/seed.py`, `tests/agent/test_seed.py`.
- Modify `src/orama_agent/server.py`, `src/orama/agent_client.py`, `src/orama/secrets.py`, `tests/agent/test_server.py`, `tests/test_secrets.py`.

**Interfaces:**
- Produces, protocol: command `seed-config {"app": "sabnzbd"|"qbittorrent", "values": {...}}` → `{"changed": bool}`.
  - Allowed `values`:
    - sabnzbd: `api_key` and `nzb_key`, each `^[0-9a-f]{32}$`.
    - qbittorrent: `password_pbkdf2`, matching `^@ByteArray\([A-Za-z0-9+/]{22}==:[A-Za-z0-9+/]{86}==\)$`.
  - Anything else → `Refused`.
  - Written as: sabnzbd `[misc]` `api_key`, `nzb_key`; qbittorrent `[Preferences]` `WebUI\Password_PBKDF2`.
  - The Agent supplies these fixed keys itself and never takes them from the request:
    - sabnzbd `[misc]`: `host_whitelist = sabnzbd, gluetun, localhost`.
    - qbittorrent `[Preferences]`: `WebUI\Username=orama`, `WebUI\LocalHostAuth=false`, `WebUI\HostHeaderValidation=false`.
- Produces, Agent `seed.py`:
  - `render(app, current_text: str | None, values) -> str | None`: returns the new file text, or `None` when unchanged.
  - Line-based patching of `key = value` (SABnzbd configobj) and `key=value` (Qt ini) inside the named section, appending the section or keys if missing. Every other line is preserved byte for byte.
  - File paths: `config/sabnzbd/sabnzbd.ini` and `config/qbittorrent/qBittorrent/qBittorrent.conf`, under `app_config_dir(roots.config, app)`.
- Produces, server: opens the file through the existing no-follow dir-fd walk.
  - The current file is read with `_read_small` semantics: regular file, O_NOFOLLOW, size cap.
  - When the content would change:
    1. Stop the container if it is running (`runner.stop(app)`, same pinned compose prefix).
    2. Write atomically: owner PUID:PGID, mode 0600.
    3. Start the container again (`runner.start(app)`), only if it was running.
- Produces, client: `AgentClient.seed_config(app: str, values: dict[str, str]) -> bool`.
- Produces, secrets:
  - `ensure_app_keys` now also creates `apikey:sabnzbd` and `nzbkey:sabnzbd` (via `generate_api_key`) and `password:qbittorrent` (via `secrets.token_urlsafe(24)`) when those apps are enabled. It never overwrites an existing value.
  - `qbittorrent_pbkdf2(password: str, salt: bytes | None = None) -> str`: PBKDF2-HMAC-SHA512, 100000 iterations, 16-byte salt, 64-byte key, rendered as `@ByteArray(<b64 salt>:<b64 key>)`. The Agent only ever receives the hash, never the password.

### Task 3: HTTP client and step engine

**Files:** Create `src/orama/wiring/{__init__,http,engine}.py`, `tests/wiring/{__init__,test_http,test_engine}.py`

**Interfaces:**
- Produces:
  - `@dataclass Response(status: int, headers: dict[str, str], body: bytes)` with `.json() -> Any`.
  - `class Http`: `request(method, url, *, headers=None, params=None, json=None, form=None, timeout=30.0) -> Response`. Built on stdlib `urllib`. `params` and `form` are URL-encoded with `urllib.parse.urlencode`. It keeps a cookie jar per instance, which qBittorrent needs. It never raises on HTTP status codes. On connection failure it raises `Unreachable(app_url)`.
  - `class FakeHttp(Http)`: routes `(method, path)` to handler callables, records every call, and can simulate `Unreachable`.
  - `@dataclass StepResult(name: str, app: str, status: Literal["changed","unchanged","failed","skipped"], message: str)`.
  - `@dataclass Step(name: str, app: str, run: Callable[[], str | None], needs: tuple[str, ...] = ())`. `run` returns a short plain message if it changed something and `None` if it changed nothing. It raises `StepError(message)` on failure.
  - `run_steps(steps: list[Step]) -> list[StepResult]`:
    - Steps run in the given order.
    - A step whose `needs` include a failed or skipped step is `skipped` with the message "waiting for <app>".
    - Any other exception becomes `failed` with "unexpected error in <app>" plus the exception type, never the exception text. The text could carry secrets.
  - `wait_until(check: Callable[[], bool], *, app: str, timeout: float, interval: float = 3.0, clock=time.monotonic, sleep=time.sleep) -> None`: raises `StepError("<App> is still starting — run apply again in a few minutes.")` on timeout. `Unreachable` counts as not ready.
  - `format_checklist(results) -> list[str]`:
    - `changed` → `✓ <App>: <message>`
    - `unchanged` → no line
    - `failed` → `✗ <App>: <message>`
    - `skipped` → `… <App>: skipped, <message>`
    - If there are no changed and no failed results → the single line `✓ Nothing to change`.

- [ ] **Step 1: Write failing tests.**
  - FakeHttp routing works and records params and json.
  - `Http` encodes `params` with awkward values. **[RF4]** Test against a local `http.server` thread on 127.0.0.1: `a&b=c%d+e #f Ταινίες` arrives intact.
  - Unreachable is raised on a refused port.
  - The engine skips dependents.
  - Exception text never appears in the result message.
  - `wait_until` times out with the exact message, using a fake clock. **[RF1]**
  - Checklist formatting, including the "Nothing to change" case.
- [ ] **Step 2: Run** `uv run pytest tests/wiring -v` → FAIL.
- [ ] **Step 3: Implement.**
- [ ] **Step 4: Run** → PASS.
- [ ] **Step 5: Commit** `feat: wiring http client and step engine`.
