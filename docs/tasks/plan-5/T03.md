## What this task is

Spec §10.1.3 and §10.3.1: on a fresh Ubuntu 24.04 runner and on a Debian 12 virtual machine
started with QEMU/KVM on the runner, with nobody touching anything: install → the setup wizard
completed by an automated browser → an episode and a film requested through Orama → a bundled
fake indexer and seeder serve generated clips → assert the download, the same-inode hardlink,
that Jellyfin lists them, that a subtitle was placed and that the request shows Ready → run
the installer again and assert nothing changed.

The plan lists what is already tested elsewhere and why that is not this proof, the files and
interfaces to create, the nine assertion groups, and five steps that each end in a commit and
a green CI run. **Steps 1–2 are complete. Step 3 is building the Ubuntu harness.**

### Step 2 — fake Torznab and generated clips (ChatGPT/Codex): needs review

- Added a keyed fixture feed, single-file torrents and a byte-range web seed, plus local contract tests.
- Added a probe to the real-container integration suite. It tests the saved Prowlarr indexer, checks
  acceptance in Sonarr and Radarr, then grabs the episode through Sonarr and checks whether
  qBittorrent fetches the fixture bytes and Bazarr writes the Greek sidecar.
- The pinned importers require at least 600 seconds for these catalogue titles. Both clips run for
  610 seconds. H.264 filler lets the fixture meet the pinned size limits with actual bytes.
  The embedded Greek ASS track is available to the provider while Orama ignores ASS on disk scans.
- Local fixture and hygiene tests (21), Ruff and ShellCheck passed. Linux CI proved app
  acceptance, episode download and subtitle extraction. Film download, the full wizard, hardlink and VM proof remain open.
- First Linux run: Prowlarr accepted the saved Torznab indexer and synced it to both Arrs.
  Sonarr then returned HTTP 503 after its upstream catalogue connection was reset, before either
  release could be inspected. The probe retries only those read-only catalogue lookups on 503.
  See [run 43283833069](https://github.com/DarkAngelGR/orama-server/actions/runs/43283833069).
- [Run 43284322845](https://github.com/DarkAngelGR/orama-server/actions/runs/43284322845) found
  both releases. Sonarr accepted the episode. Radarr rejected WEBDL-1080p under the default
  Mixed movie profile. The probe now applies Orama's supported 1080p quality choice and the
  Samsung S95F profile before searching, then restores the prior setup. Use the same quality
  choice in the wizard harness when it requests the 1080p fixtures.
- On [run 43286020192](https://github.com/DarkAngelGR/orama-server/actions/runs/43286020192)
  at `8d46eff`, Prowlarr accepted and synced the generic Torznab feed; Sonarr and Radarr
  accepted their releases; qBittorrent fetched the episode from the trackerless web seed;
  Sonarr imported it; and Bazarr wrote a Greek SRT containing the embedded fixture text.
  The unit, browser, images and integration jobs passed (2,155 unit and 44 integration tests;
  the integration test phase took 7m 15s). The probe also passed at Gemini's docs-only
  `238c8aa` ([run 43287636683](https://github.com/DarkAngelGR/orama-server/actions/runs/43287636683),
  integration test phase 7m 39s). A tracker and second seeder were unnecessary.
