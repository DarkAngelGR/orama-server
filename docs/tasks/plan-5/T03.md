## What this task is

Spec §10.1.3 and §10.3.1: on a fresh Ubuntu 24.04 runner and on a Debian 12 virtual machine
started with QEMU/KVM on the runner, with nobody touching anything: install → the setup wizard
completed by an automated browser → an episode and a film requested through Orama → a bundled
fake indexer and seeder serve generated clips → assert the download, the same-inode hardlink,
that Jellyfin lists them, that a subtitle was placed and that the request shows Ready → run
the installer again and assert nothing changed.

interfaces to create, the nine assertion groups, and five steps that each end in a commit and

### Review of steps 2-3 (Claude, 2026-11-13)

Step 2 is reviewed and fine. Step 3 is not done until the points below are fixed. The line
numbers are those of `tests/e2e/test_e2e.py` and `.github/workflows/e2e.yml` on branch `test`
at the time of the review. Claude does not edit `tests/e2e` or the e2e job; this list is for
the tool that owns step 3.

MUST-FIX before step 3 counts as done:

1. **The leak scan over saved files cannot fail, and the wizard output is not scanned**
   (`tests/e2e/test_e2e.py:629-631`). Every file in `log_dir` was written through
   `target.scrub()` (lines 340, 438, 576), so scanning them finds nothing by construction. The
   container-log files that CI really uploads are written later, at teardown, and are never
   scanned. The wizard's stdout and stderr, the page texts and the pytest output are outside
   the scan as well. Fix: write the container-log files inside the test before the scan and scan
   the final files; scan the wizard output and the page bodies raw, before scrubbing; and after
   the install assert that a POST with the old setup code is refused (proof that the one-time
   code is spent, which is why printing it once is allowed).
2. **Three green runs in a row are required, and the job must fail instead of skipping**
   (`.github/workflows/e2e.yml:48`, `tests/e2e/conftest.py:98`). Only one green run has been
   seen, on a later commit than the one reviewed. Record three consecutive green run links in
   this file. When the target variable `ORAMA_E2E_TARGET` is missing, conftest calls
   `pytest.skip`, so a dropped variable turns the job green with 0 passed. Fix: in CI (when
   `CI` is set) fail instead of skipping, or make the e2e step fail unless pytest reports
   exactly 1 passed.
3. **The "subtitle newer than the import" check uses the wrong timestamp**
   (`tests/e2e/test_e2e.py:552-553`). It compares the .srt time with the hard-linked video's
   mtime, which is when the torrent data was written, not when Sonarr or Radarr imported it,
   so any subtitle written after the download passes. Fix: take the import time from the
   Sonarr or Radarr history, or from the ctime of the media link; or drop the claim and keep
   the content check (the Greek text exists only in the embedded track).
4. **Actions and the python image are not pinned** (`.github/workflows/e2e.yml:21,24,25,51`,
   `tests/e2e/test_e2e.py:252`). `actions/checkout@v4`, `astral-sh/setup-uv@v6`,
   `actions/setup-node@v4` and `actions/upload-artifact@v4` are pinned by tag only, and
   `python:3.12-slim` by tag. Pin the actions to commit ids as `ci.yml` does, give setup-uv a
   version, and pin the python image by digest. Scan the folder that is uploaded as an
   artifact before `upload-artifact` runs.

of this round (commit "fix: refresh Jellyfin from the worker, debounced, never in the
webhook"). The webhook no longer calls Jellyfin; it records "media changed" and wakes the
