### What was built (`04ef940`)

- **Publish gate.** The `publish` job (it moves the version tag that users install) now needs
  `unit`, `images`, `browser` and `integration`. `tests/test_ci_workflow.py` checks it. The
  `browser` job had passed more than three runs in a row before it became a gate.

  client waits.

  `test_debian_12_installer_and_agent_self_update_contract` runs the installer on the
  **Ubuntu** CI runner with a Debian 12 `os-release` file. It shows that the installer picks
  "debian", that a second run changes nothing, and that the live Agent refuses arguments to
  `self-update`.

### Correction (Claude, 2026-11-11)

The first version of this report, and `docs/STATUS.md`, said that Debian 12 was "verified in
CI" and described this task as "Publish gate & end-to-end VM verification". That was not true:

- No Debian 12 machine has run the installer. The test above runs on Ubuntu. Docker is already
  installed there, so the installer's steps that set up Docker's package source for Debian do
  not run in it; only dry-run unit tests (`tests/test_install_sh.py`) cover them.
- None of the end-to-end proof in the spec (§10.1.3) exists: no clean-machine install driven
  through the wizard by a browser, no request through a fake indexer and seeder, no check of
  the download, the hardlink, the media server, the subtitle or "Ready", on either Ubuntu
  24.04 or Debian 12.

So this task is now only what was really done, the publish gate, and it is **done**. The
end-to-end proof is its own task, **Task 3, open, not started**; see `T03.md`.
