### Review fixes (Claude, 2026-11-11, `fix: harden and unblock Orama self-update`)

What was wrong, in plain words, and what changed:

1. **The helper had more access than it needed.** It was started with the Docker socket, the
   whole Orama folder writable, default capabilities and a network. It now has no network, no
   capabilities, no way to gain privileges, a read-only file system, the Orama folder read-only,
   and process and memory limits. Its command line is fixed and tested item by item.
2. **One update blocked everything else.** While images downloaded (up to an hour), Settings
   saves and applies were refused and the Agent answered nothing else. The update is now two
   Agent commands: `self-update-pull` (download; holds no Orama lock and only its own Agent
   lock) and `self-update` (restart; a few seconds, only while no apply runs).
3. **The success message was not true.** "Orama is up to date." appeared after any update. The
   page now says "Update started. Orama restarts by itself if a newer version was downloaded —
   reload this page in a minute.", or, when nothing newer was downloaded, "Orama is already on
   the newest version. Nothing was changed." (and then nothing is restarted at all).
4. **Offline or failed downloads** now give "Orama could not download the update, so nothing was
   changed. Check the internet connection and try again." No container is touched.
